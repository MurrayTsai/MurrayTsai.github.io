  • 用户在弱网环境下，自动降低清晰度或加载缓存。

这就是超出用户预期的体验。

十二、从事情本身收集需求：因和果

需求不仅来自用户，也来自事情本身。

可以从“因”和“果”两个方向分析。

视角 方法 说明
从“因”分析 业务分析 分析业务为什么出现问题，业务目标是什么
从“因”分析 文献 / 历史经验 / 市场数据 查行业报告、历史案例、市场数据，理解问题形成原因
从“因”分析 头脑风暴 让业务、用户、运营、研发、管理层一起提出想法
从“果”分析 竞品分析 看市场上类似产品怎么解决，功能和方案如何设计
从“果”分析 经营数据 / 行为数据 看产品上线后的真实数据，发现用户行为和业务问题

简单理解：

产品经理不能只听用户说。

还要看业务、数据、市场、竞品和历史经验。

十三、一手需求和二手需求

需求可以分成一手需求和二手需求。

类型 含义 优点 缺点
一手需求 用户直接提出，未经过加工 更真实、更接近原始问题 收集效率低，难以覆盖大量用户
二手需求 别人转述、部门反馈、数据汇总后的需求 效率高，覆盖范围广 容易被转述者理解偏差或加工变形

实际工作中，不能只要一手需求，也不能只要二手需求。

可以全员收集需求，但由产品经理统一整理、去重、追问、辨别和排序。

十五、需求优先级四象限

需求可以按“强烈”和“高频”分成四类。

需求类型 处理策略 原因
真实 + 强烈 + 高频 立即做 价值最高，是核心刚需
真实 + 强烈 + 低频 有计划地做 重要但不常用，可以排进版本计划

十八、用户故事卡片模板

一个完整的用户故事卡片可以包含这些字段：

部分 内容

目标 他想做什么？例如就近接单、查询订单、申请退款
原因 / 价值 为什么要做？例如多赚钱、节省时间、减少等待
前提条件 故事发生前必须满足什么？例如用户已登录、已开启定位

期望结果 系统应该给出什么结果？例如展示附近订单、返回政策答案

这个模板可以帮助产品经理把需求写得更完整。
